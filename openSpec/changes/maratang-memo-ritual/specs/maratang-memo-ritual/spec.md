## ADDED Requirements

### Requirement: 시작 화면에 히스토리와 메모 입력이 보여야 한다
시스템은 마라탕이 생성되기 전, 왼쪽 히스토리 목록과 중앙 메모 입력 영역이 있는 데스크톱 우선 시작 화면을 MUST 보여야 한다.

#### Scenario: 사용자가 앱을 연다
- **WHEN** 사용자가 활성 마라탕이 없는 상태로 경험을 연다
- **THEN** 화면은 왼쪽에 히스토리 목록을, 중앙에 메모 입력 영역을 보여야 한다
- **AND** 화면에는 아직 조리 장면이 나타나지 않아야 한다

#### Scenario: 사용자가 메모 제목을 입력한다
- **WHEN** 사용자가 입력 영역에 메모 제목을 입력한다
- **THEN** 그 제목은 마라탕 주문명으로 사용할 수 있어야 한다

### Requirement: 조리 화면에는 재료와 영수증 배치가 보여야 한다
시스템은 사용자가 마라탕을 만들면 중앙의 마라탕 냄비, 재료 트레이, 오른쪽 고정 영수증 패널이 있는 조리 화면을 MUST 보여야 한다.

#### Scenario: 마라탕이 생성된다
- **WHEN** 사용자가 메모 제목으로 마라탕을 시작한다
- **THEN** 시스템은 조리 화면을 보여야 한다
- **AND** 영수증 패널은 오른쪽에 유지되어야 한다
- **AND** 재료 트레이는 냄비 아래에 나타나야 한다

#### Scenario: 초기 조리 상태가 국물만 있다
- **WHEN** 사용자가 새 마라탕을 시작한다
- **THEN** 냄비는 국물만 있는 빈 상태로 시작해야 한다
- **AND** 재료는 사용자가 직접 선택해서 추가해야 한다

#### Scenario: 재료가 추가된다
- **WHEN** 사용자가 재료를 냄비에 추가한다
- **THEN** 냄비의 시각 상태가 업데이트되어야 한다
- **AND** 영수증은 그 재료를 포함해 갱신되어야 한다
- **AND** 총 가격이 증가해야 한다

### Requirement: 맵기 선택과 추적이 가능해야 한다
시스템은 조리와 먹기 과정에서 마라탕 맵기를 설정하고 변경할 수 있게 MUST 해야 하며, 현재 맵기는 계속 보이게 유지해야 한다.

#### Scenario: 사용자가 조리 중 맵기를 바꾼다
- **WHEN** 사용자가 조리 화면에서 맵기를 조절한다
- **THEN** 현재 맵기 값이 즉시 업데이트되어야 한다
- **AND** 새 값은 영수증 또는 맵기 표시 영역에 반영되어야 한다

#### Scenario: 맵기가 먹기 화면으로 이어진다
- **WHEN** 사용자가 조리를 끝내고 먹기 화면으로 들어간다
- **THEN** 현재 맵기 값은 유지되어야 한다

### Requirement: 먹기 과정은 맵기를 올리고 기절을 유발할 수 있어야 한다
사용자가 마라탕을 반복해서 먹으면 맵기가 올라가야 하며, 맵기 100 도달 시 10초 기절 상태를 MUST 유발해야 한다.

#### Scenario: 반복 먹기로 맵기가 오른다
- **WHEN** 사용자가 먹기 화면에서 재료를 반복해서 먹는다
- **THEN** 맵기 값은 시간이 지남에 따라 증가해야 한다
- **AND** 맵기 표시기는 값이 올라갈수록 위로 이동해야 한다

#### Scenario: 맵기가 최대치에 도달한다
- **WHEN** 맵기 값이 100에 도달한다
- **THEN** 시스템은 10초 동안 기절 상태에 들어가야 한다
- **AND** 기절 동안 먹기 조작은 비활성화되어야 한다

### Requirement: 먹기 화면에는 마라탕 중심과 맵기 표시가 보여야 한다
시스템은 완성된 마라탕을 중앙에 두고, 오른쪽에 맵기 슬라이드 또는 표시기를 배치한 단순화된 먹기 화면을 MUST 보여야 한다.

#### Scenario: 사용자가 먹기 화면에 들어간다
- **WHEN** 마라탕이 완성된다
- **THEN** 화면은 완성된 마라탕만 주요 시각 초점으로 보여야 한다
- **AND** 오른쪽에는 맵기 표시기가 보여야 한다

#### Scenario: 사용자가 계속 먹는다
- **WHEN** 사용자가 완성된 마라탕을 먹는다
- **THEN** 마라탕은 계속 주요 초점으로 유지되어야 하며 맵기 표시기는 변해야 한다

### Requirement: 완료 동작과 축하 상태가 있어야 한다
시스템은 사용자가 조리 또는 먹기 상태에서 완료 동작을 실행하면 축하 연출이 있는 완료 상태로 전환되게 MUST 해야 한다.

#### Scenario: 사용자가 마라탕을 완료한다
- **WHEN** 사용자가 완료 동작을 실행한다
- **THEN** 시스템은 완료 메시지와 축하 효과를 보여야 한다
- **AND** 세션은 완료로 표시되어야 한다

#### Scenario: 완료 상태가 표시된다
- **WHEN** 시스템이 완료 상태에 도달한다
- **THEN** 축하 효과 아래에는 마라탕 장면이 계속 보여야 한다

### Requirement: 히스토리 항목은 저장된 마라탕 장면을 복원해야 한다
시스템은 완료되었거나 진행 중인 마라탕 장면을 히스토리 목록에 저장하고, 사용자가 히스토리 항목을 클릭하면 저장된 마라탕 상세를 복원해야 한다.

#### Scenario: 사용자가 히스토리 항목을 클릭한다
- **WHEN** 사용자가 히스토리 목록에서 항목 하나를 선택한다
- **THEN** 시스템은 해당 메모의 상세 화면을 열어야 한다
- **AND** 저장된 마라탕 장면을 그 화면에서 복원해야 한다

#### Scenario: 저장 상태가 새로고침 후에도 남는다
- **WHEN** 사용자가 페이지를 새로고침한다
- **THEN** 로컬 저장소가 유효하다면 이전 히스토리 항목은 계속 사용 가능해야 한다

#### Scenario: 히스토리에 조리 타임라인이 남는다
- **WHEN** 사용자가 마라탕을 조리하고 먹는 과정이 진행된다
- **THEN** 히스토리에는 최종 상태뿐 아니라 조리 전체 타임라인도 저장되어야 한다

### Requirement: 상세 화면은 넓은 마라탕 장면을 우선해야 한다
시스템은 히스토리에서 항목을 열었을 때 왼쪽 히스토리 패널을 접고, 마라탕 장면이 더 넓게 보이는 상세 화면을 MUST 보여야 한다.

#### Scenario: 사용자가 상세 화면을 연다
- **WHEN** 사용자가 히스토리 항목을 클릭해 상세 화면에 들어간다
- **THEN** 왼쪽 히스토리 패널은 접혀 있어야 한다
- **AND** 마라탕 장면이 더 넓은 가로 공간을 차지해야 한다

### Requirement: 메모와 마라탕 상태는 로컬에 저장되어야 한다
시스템은 메모 히스토리, 재료 상태, 맵기 상태, 완료 상태를 로컬에 저장해서 나중에 다시 열 수 있게 MUST 해야 한다.

#### Scenario: 사용자가 조리 후 새로고침한다
- **WHEN** 사용자가 마라탕을 만든 뒤 페이지를 새로고침한다
- **THEN** 저장된 메모 히스토리와 마라탕 상태는 로컬 저장소에서 복원되어야 한다

#### Scenario: 저장된 데이터가 유효하지 않다
- **WHEN** 저장된 데이터를 파싱할 수 없거나 호환되지 않는다
- **THEN** 시스템은 안전한 빈 히스토리 상태로 되돌아가야 한다

#### Scenario: 기절 타이머는 백그라운드에서도 진행된다
- **WHEN** 사용자가 기절 상태에서 탭을 백그라운드로 보낸다
- **THEN** 기절 타이머는 멈추지 않고 계속 진행되어야 한다
