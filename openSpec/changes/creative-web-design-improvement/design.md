## 배경

이 변경은 제품 동작을 다시 만드는 작업이 아니라 시각적 개편입니다. 구현은 기존 콘텐츠, 상호작용, 데이터 흐름을 유지하면서 표현 계층을 재구성해야 합니다.

## 목표 / 비목표

**목표:**
- 더 독특하고 창의적인 시각 정체성을 만듭니다.
- 계층 구조, 가독성, 완성도 인상을 개선합니다.
- 이해를 돕고 방해하지 않는 모션과 시각적 포인트를 추가합니다.
- 가능한 범위에서 기존 제품 구조를 유지합니다.

**비목표:**
- 백엔드나 API 변경은 하지 않습니다.
- 정보 구조를 대규모로 다시 설계하지 않습니다.
- 콘텐츠 전략을 전면 개편하지 않습니다.

## 결정 사항

- 일회성 페이지 리디자인보다 섹션 중심의 시각 시스템을 사용합니다.
  - 이유: 페이지 전반에서 일관성과 재사용성을 유지할 수 있습니다.
  - 대안: 페이지마다 완전히 다른 레이아웃을 쓰는 방식은 불일치와 유지보수 비용을 키웁니다.
- 색상, 간격, 라운드, 그림자, 모션을 위한 더 촘촘한 디자인 토큰 계층을 도입합니다.
  - 이유: 창의적인 표현을 일관되게 적용하고 조정하기 쉬워집니다.
  - 대안: 개별 스타일 오버라이드는 초기 속도는 빠르지만 UI를 빠르게 분절시킵니다.
- 짧은 지속 시간과 문맥을 고려한 전환을 가진 절제된 모션을 우선합니다.
  - 이유: 프리미엄한 느낌을 주면서도 성능과 사용성을 해치지 않습니다.
  - 대안: 더 강한 애니메이션은 콘텐츠 집중을 방해하고 상호작용을 느리게 만들 수 있습니다.
- 구현은 기존 프론트엔드 컴포넌트와 스타일 프리미티브 안에서 대부분 처리합니다.
  - 이유: 마이그레이션 위험을 줄이고 불필요한 구조 변경을 피할 수 있습니다.
  - 대안: 새로운 디자인 시스템 계층 도입은 이 변경 범위에는 과합니다.

## 위험 / 트레이드오프

- [창의적인 스타일이 가독성을 떨어뜨릴 수 있음] -> 주요 콘텐츠 블록 기준으로 대비, 타이포그래피 크기, 여백을 검증합니다.
- [일부 페이지에서 모션이 과하게 느껴질 수 있음] -> 작고 목적이 분명한 전환만 사용하고 reduced-motion 대안을 둡니다.
- [더 강한 시각 시스템이 기존 컴포넌트의 불일치를 드러낼 수 있음] -> 공통 토큰을 먼저 적용하고, 예외 컴포넌트를 순차적으로 다듬습니다.
- [범위가 제한된 리디자인은 일부만 바뀐 것처럼 느껴질 수 있음] -> 가시성이 높은 영역부터 우선 적용하고 스타일 언어를 일관되게 유지합니다.
