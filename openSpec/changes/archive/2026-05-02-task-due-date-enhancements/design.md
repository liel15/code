## 배경

현재 작업에는 시간 기준이 없어 우선순위 판단과 검토가 어렵고, 완료 이후의 보상 구조도 없습니다. 이 변경은 마감일과 나무 보상 시스템을 붙여 기한을 표현하고, 지연 작업을 강조하며, 완료에 대한 시각적/경제적 보상을 제공합니다.

## 목표 / 비목표

**목표:**
- 작업 생성 시 마감일 입력을 요구하고 이후 수정할 수 있게 합니다.
- 목록과 상세 화면에 마감일을 분 단위까지 표시합니다.
- 마감일로부터 지연 및 임박 상태를 계산합니다.
- 마감일 기준 정렬과 필터링을 지원합니다.
- 각 작업에 나무를 연결하고 성장, 시들음, 판매 상태를 보여줍니다.
- 완료 보상으로 코인을 지급하고, 코인으로 장식 아이템을 구매하게 합니다.

**비목표:**
- 알림 또는 리마인더.
- 반복 작업.
- 캘린더 동기화.
- 다단계 일정 관리 흐름.
- 실제 화폐 결제.
- 사용자 간 거래.
- 소셜 경쟁 기능.

## 결정 사항

### 마감일은 ISO-8601 타임스탬프로 저장한다
작업 모델에 `dueDate` 필드를 두고 ISO-8601 타임스탬프로 저장합니다. 생성 시에는 필수 입력으로 처리하고, 수정 시에는 변경 가능하게 둡니다.

대안:
- 날짜와 시간을 분리한 필드: UI와 검증 복잡도만 증가합니다.
- 상대적 기한 텍스트: 정렬과 필터링을 안정적으로 지원할 수 없습니다.

### 긴급도는 현재 시간으로부터 계산한다
지연/임박 상태를 별도 저장하지 않고, 렌더링 또는 조회 시 계산합니다. 임박은 예정일 기준 7일 이내로 계산합니다.

대안:
- 상태 플래그 저장: 상태가 오래될 수 있고 별도 관리가 필요합니다.
- 작업으로 상태 갱신: 표시용 기능에 운영 복잡도를 더합니다.

### 정렬과 필터는 기존 작업 조회 경로에 통합한다
기존 작업 조회 경로를 확장해 마감일 정렬과 필터가 모든 화면에서 일관되게 동작하도록 합니다.

대안:
- 클라이언트 전용 정렬: 서버 결과와 어긋날 수 있고 확장성이 떨어집니다.
- 별도 엔드포인트: 작업 조회가 더 복잡해질 때까지는 불필요합니다.

### 나무 상태는 작업 상태와 마감일로부터 도출한다
나무의 성장, 시들음, 수확 가능 상태는 작업 완료 여부와 마감일을 기준으로 계산합니다. 별도 배치 작업 없이 화면에서 상태를 판정하되, 판매 여부와 코인 지급 여부는 영속화합니다.

대안:
- 나무 상태를 전부 저장: 상태 불일치와 동기화 비용이 큽니다.
- 배치 작업으로 상태 갱신: 운영 복잡도가 커집니다.

### 코인과 장식은 별도 영속 데이터로 관리한다
코인 잔액, 구매한 장식품, 판매 완료 여부는 별도로 저장합니다. 작업별 나무는 시각 요소이고, 경제 상태는 계정 단위로 유지합니다.

대안:
- 모든 것을 작업에만 저장: 코인과 장식 관리가 어려워집니다.
- 외부 상점 서비스 분리: 아직 범위가 과합니다.

## 위험 / 트레이드오프

- [시간대 혼동] → 저장값은 UTC로 정규화하고 화면에서는 사용자의 로컬 시간대로 표시합니다.
- [임박 라벨 불일치] → 7일 범위를 문서화하고 목록과 상세 화면에서 동일하게 유지합니다.
- [부분 적용] → 마감일이 없는 기존 작업은 그대로 유효하며 시간 표시 없이 렌더링합니다.
- [경제 밸런스] → 코인 지급과 장식 가격을 작게 시작하고 추후 조정 가능하게 둡니다.
- [중복 보상] → 판매 여부를 별도 저장해 코인 중복 지급을 막습니다.

## 마이그레이션 계획

1. 작업 저장소와 검증에 due date, 나무 상태, 코인, 장식 구매 상태를 추가합니다.
2. 작업 생성/수정 흐름이 마감일을 필수 입력받고 이후 수정하도록 변경합니다.
3. 작업 목록과 상세 화면이 마감일, 나무 상태, 보상 UI를 표시하도록 수정합니다.
4. 정렬과 필터링 로직이 새 필드를 사용하도록 확장합니다.
5. 필요 시 읽기/쓰기 경로에서 보상 관련 필드를 무시하는 방식으로 롤백합니다. 기존 작업은 계속 사용할 수 있습니다.

## 열린 질문

현재 남은 질문 없음.
